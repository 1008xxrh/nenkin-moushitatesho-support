# 設計の概要（レビュー用）

2026年10月24日作成。対象は2026年10月21日に公開した版です。レビューのために、作者がAI（Claude）と一緒に、今のコードと照らし合わせて書きました。場所は行番号ではなく、関数名などで示しています。

## 1. どんなアプリか

- 障害年金の「病歴・就労状況等申立書」の**下書き**を作るWebアプリです。社労士や年金事務所に渡す下書きまでを目指していて、提出書類そのものを完成させるものではありません。
- 使う人は、うつ病・発達障害などの当事者です。頭の負担を減らすことを最優先にしています（1問ずつ聞く、答えなくても進める、途中でやめられる）。
- **サーバーはありません。** GitHub Pagesで静的に配信しています。入力はブラウザの localStorage にだけ保存し、外へは送りません。

## 3. `index.html` の中の並び

1. `<head>` と CSS（色の変数、画面の部品、下書きの紙面、配置画面、小窓）
2. 画面の入れ物：`#taskHeader`（上の章のボタン）・`#screen`（本文）・`#footerNav`（下の帯）・`#helpOverlay`（ヘルプの小窓）・`#bandDetailOverlay`（通院の詳しい小窓）
3. 埋め込んだ ExcelJS（とても長い1か所）
4. アプリのスクリプト：
   - 様式のExcel：`TEMPLATE_02_XLSX_BASE64`（申立書）・`TEMPLATE_04_XLSX_BASE64`（続紙）。日本年金機構の公式のExcelを base64 で持っています
   - Excelへの書き出し：`exportToOfficialForm`（入口）、`buildPeriodsForForm`（期間の行を作る）、`splitGapIntoChunks`（長い期間を区切る）、`dateToWareki`・`yearToWareki`（和暦）、`downloadXlsxBuffer`
   - 保存データ：`makeInitialState`（全部の項目）、`CURRENT_STATE_VERSION`（今は16）、`migrateAppState`（古い版のデータを今の形に直す）
   - 画面の移動：`STEPS`（画面ID→関数。31画面）、`showScreen`・`goTo`・`goBack`・`finishChapter`・`renderTasks`・`setFooter`
   - 保存・DL保存・復元：`saveStateToStorage`・`scheduleDebouncedSave`・`loadStateFromStorage`・`buildBackupPayload`・`handleDlSaveClick`・`validateBackupFile`・`applyRestorePayload`・`renderRestoreConfirmScreen`・`stepResumeCheck`
   - 通院していない時期：`computeCoverageHoles`・`computeGaps`
   - 各画面の関数（`stepStart`、`stepCh4Summary`、`stepCh5Place`、`stepCh5Preview` など）
   - 姉妹ページとの受け渡し：`applyAdlHandoff`・`getAdlHandoffPreviewItems`（今の状況）、`applyAdlHandoffNinteibi`（認定日ごろ）
   - 起動：保存があれば再開の画面（`stepResumeCheck`）、無ければ最初の画面

## 4. 画面の流れ

```
最初の画面 → 生まれた年 → 年表の区切り（3年／5年）
→ 第1章 仕事をしているか → 仕事の詳しいこと（会話形式）または 仕事をしていない理由（会話形式）
→ 第2章 日常生活10項目（会話形式）→ その他の困りごと
→ 第3章 出来事カードを選ぶ
→ 第4章 通院の記録（病院名 → 期間 → 日付の確かさ）→ 通院の一覧 ⇄ 通院していない時期の理由
→ 第5章 出来事を年表に置く → 年表ができました → 下書き確認（Excel出力）
→（下書きを見たあと）障害認定日ごろの状況・障害者手帳
```

- 上の章のボタンで、いつでも好きな章へ行けます。下書きを一度見ると、章のボタンに「認定日ごろ」「障害者手帳」「下書き」が増えます。
- 会話形式の画面は、答えのある所の次から再開します。答えた質問は、あとから押し直せます。

## 5. 保存のしくみ

| 保存場所（localStorage のキー） | 中身 |
|---|---|
| `shinritsusho_draft_v1` | 本体の入力のすべて（state）と、今の画面・戻る履歴 |
| `shinritsusho_dl_save_marker_v1` | 最後にDL保存した内容の指紋（同じ内容ならファイルを増やさないため） |
| `adl_` で始まるもの | 姉妹ページの入力。`adl_handoff_v1`・`adl_handoff_ninteibi_v1` は本体への受け渡し用 |

- **自動保存**：入力や操作のたびに、800ミリ秒待ってから保存します（`scheduleDebouncedSave`）。画面を離れたとき（`visibilitychange` の hidden と `pagehide`）にも保存します。
- **再開の画面**：保存があると、起動時に「前回の続きがあります」を出します。この画面が出ている間は保存しません（空の状態で上書きしないため）。
- **DL保存**：入力の全部（本体と姉妹ページ）を1つの .json にしてダウンロードします。形は `{app, fileFormat, exportedAt, main: {state, current, historyStack, savedAt}, sub: {adl_…}}`。内容が前回と同じなら、ファイルを増やしません。
- **ファイルから戻す**：`validateBackupFile` で、このアプリのファイルか、新しい版で作られていないかを確かめてから、確認の画面を出します。戻すと、端末の内容はファイルの内容に**置きかわります**（足し合わせはしません）。
- 古い版のデータは、読み込むときに `migrateAppState` で今の形に直します。

## 6. Excelへの書き出し

- 埋め込んだ公式のExcelを ExcelJS で読み、セルに書いてダウンロードします。シートの保護はそのまま残します。
- 期間の行は、通院の記録と、通院していない時期をもとに作ります。5年（区切りが3年なら3年）を超える期間は区切ります。区切った最後の端数が7か月未満なら、前の行に含めます。
- 申立書（02）に5行まで書きます。それより多いときは続紙（04）を別のファイルで出します。続紙は1組（表と裏）に11行で、足りなければ組を増やします。
- 元号は月まで見て決めます（2019年4月は平成31年、2019年5月は令和1年）。
- 傷病名・発病日・初診日は、聞かないので空欄のまま出します。

## 7. 意図してこうしている所（変えるときは理由を聞いてください）

- **外へ送らない**：外へ通信する命令は使っていません。アプリのコードに、外のアドレスは出てきません（埋め込んだ部品のライセンス表示のコメントを除く）。
- **病名を扱わない**：入力の例にも病名を入れていません。
- **答えなくても進める・途中でやめられる**：答えないと進めないのは、生まれた年・年表の区切り・仕事をしているかの3つだけです。
- **本人が言っていないことを書かない**：分からない所を、アプリが推測で埋めません。下書きには「未入力」「理由：未記入。」と、そのまま出します。
- **症状の言葉を丸めない**：チェックの項目の言い方を、読みやすさのために弱めません。
- **DL保存のボタンは、わざと小さい**：押すたびにファイルが増えるので、押し間違いを減らすために小さくしてあります。
- **姉妹ページの答えは、自動では反映しない**：本体の画面で「取り込む」を押したときだけ反映します。
- **画面は明るい色だけ**：`<meta name="color-scheme" content="only light">`。端末が暗い色の設定でも、ブラウザが勝手に色を変えないようにしています。

## 8. 把握している課題

- **2つのタブで開くと、古いタブが新しい入力を消す**：別のタブで保存されたことに気づくしくみが無いためです。Chromiumで再現しました。姉妹ページはわざと別のタブで開く作りなので、直すときはそこと合わせて考える必要があります。
- **幅320で、出来事カード配置の画面が詰まる**：手札の4枚目以降が下の帯に隠れ、案内の文がカードの後ろに重なります。
- **押す所が小さい所がある**：「？」は20×20、文字のリンクは高さ18など。
- **外とつながらない宣言（Content-Security-Policy）は入れていない**：入れるかどうかは、まだ決めていません。
- **公開リポジトリとREADMEのずれ、古いテスト8本**（2章のとおり）。
